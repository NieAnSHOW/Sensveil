# 多显示器保护修复

日期：2026-10-14。

## 问题与范围

连接第二台显示器后，旧材料协调器通过 `screenFrames.count == 1` 拒绝所有窗口；`backingScale == 2` 还拒绝 1x 显示器。通用材料拒绝信息包含 display，状态页因此显示“窗口所在显示器无法确认”，实际并非窗口匹配失败。

按用户本次修复要求，保护与退出过渡改为检查每个窗口的实际显示器归属。CG 与 AppKit 继续使用主屏作为全局坐标转换基准，保留显示器左侧或上方的负坐标，不按各副屏重新翻转坐标。外扩后的覆盖矩形必须完整位于唯一有效显示器内，材料 panel 必须使用正常 1x/2x 比例。屏幕布局变化使旧证据失效并重建，不能继续复用原布局的保护或退出状态。

未增加屏幕捕获、权限请求、配置迁移或不透明遮罩。跨屏、屏幕边缘覆盖不完整、异常比例、未知系统环境、减少透明度、层级冲突及权限失效继续拒绝保护。

## 验证计划

- 先以回归测试复现多屏和 1x 拒绝，再检查主/副屏、负坐标布局、跨屏与布局改变后的重验。
- 完整运行 Swift 测试套件。
- 有限合成窗口命令 `SensveilApp --validate-guard-label` 使用真实完整显示器布局，在各显示器运行生产材料 panel 和自然 CG 快照检查；不读取用户配置或捕获像素。
- 按默认构建脚本构建、签名、安装并启动产品；系统拒绝执行时停止，不改变系统安全设置。

## 证据边界

规则测试和合成窗口运行可验证定位、层级、文案及恢复行为。它们不能证明新显示器上的实际材料像素不可读、跨屏保护、全部显示器模式或跨系统兼容性；本次不将这些项目记为已验收。

## 本轮结果

回归测试修复前在 13 项材料验收测试中出现 9 次断言失败，覆盖双屏/1x 拒绝、布局改变后的重建与退出行为。修复后聚焦 13 项和完整 220 项 XCTest 全部通过。用例包括主/副屏、左右/上下布局、1x/2x、异常比例、跨屏、边缘覆盖、重复屏幕归属、布局变更重验及退出清理。

实际两屏合成命令退出 0：主屏 1x 与副屏 2x 各 33/33 检查通过，总计 66/66。使用生产材料 panel、完整真实显示器布局及自然 CG 元数据，检查首次请求隐藏文案、后续验证显示、三档切换、开关、移动、缩放、居中、点击穿透、前台退出、快速重新保护和各过渡选项。没有读取用户配置或捕获屏幕像素，没有进行物理插拔测试。

默认 release 构建脚本退出 0，三个 bundle 的 plist 与严格 ad-hoc 签名检查通过，只有产品安装并启动于约定的系统 Applications 目录。未自动选择证书、重置权限或修改系统安全设置。
