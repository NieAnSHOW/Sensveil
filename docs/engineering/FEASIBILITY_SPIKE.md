# macOS 模糊保护可行性验证

状态：轮廓探针已有两个静态未验证候选、研究已停止清除结果；材料局部正向、整体未通过，SCK 模糊替代条件仍 BLOCKED · 日期：2026-10-11，2026-10-14 更新 · 依据：[PRD](../product/PRD.md)

2026-10-14 后续产品决策：用户已批准统一圆角外扩完整包围窗口，真实轮廓识别不再是几何实现前提。该决策允许 Task 8 的几何子项实施；材料隐私、层级、输入和时延门槛继续保留。规范见 [ADR-002](../architecture/ADR-002-expanded-rounded-overlay.md)，下方真实轮廓实验记录保留历史含义，不据此阻断新几何方案，也不把需求变更算作材料通过。

## 验证问题

在只使用公开 API 的前提下，能否让 Sensveil 在指定应用失焦时对所有受支持可见窗口作不可辨识的模糊，并在聚焦时无阻碍地恢复？需要同时保持其他应用的层级、输入及系统空间行为正确。

用户明确拒绝不透明遮罩。PoC 的结论可以是某路径不成立；不能以实色覆盖证明本需求可行。

## 候选顺序

1. 以不抢焦点的 AppKit 覆盖窗口承载 `NSVisualEffectView` behindWindow 材料，验证跨应用背景模糊、系统设置变化、真实可读性。
2. 如材料路径不满足，验证 ScreenCaptureKit 按目标窗口采集 → Core Image 可控模糊 → 覆盖窗口。原始像素仅在本机内存，不先显示原始帧再补滤镜。
3. 两条都无法同时满足隐私效果、层级和交互时，输出否定结论与具体证据，回到产品决策；不引入私有 CGS API，不偷偷降级遮罩。

## 环境与测量方法

- 基线：macOS 14 和当前稳定系统各至少一台；Apple Silicon 与 Intel 各至少一台，未测试组合标为未验证。
- 应用：Safari、TextEdit、Terminal、一个实际 Electron 应用；多窗口、sheet、弹窗与 helper 分开记录。
- 显示：单屏与双屏，Retina 与非 Retina 混合缩放，窗口跨屏、显示器拔插、不同原点和负坐标。
- 数据：使用虚构姓名、手机号、财务表格及 12/24/48pt 正文，不使用真实个人信息。
- 性能：记录设备、OS、分辨率、窗口数、刷新率、CPU（100% 为一核心）、驻留内存、渲染/采样成本。
- 延迟：单调时钟记录焦点事件、覆盖呈现与撤层；100 次切换的 p50/p95/最大值；另记录新窗口首次呈现到模糊的曝光时间。
- 可读性：约 50cm 正常缩放下，至少 3 名独立评估者尝试读出测试文本；原始帧不得被显示。主观可读性测试是发行条件之一，并非密码学保密保证。

## 三档材料与安全过渡实验协议（2026-10-13 准备，完整矩阵未完成）

目的：在只使用公开 API 的前提下，逐档判定 behind-window 材料能否让 12/24/48pt 内容不可辨（F-05），并验证整体过渡不是从透明状态开始。本协议不改变下面的结论分类；它只把 F-05 从“无候选”变成“有三档可测”。

先决条件：已安装/构建的合成 fixture（3 个内容窗口，唯一标题，12/24/48pt 虚构文本）与诊断 app（`Sources/SensveilPoC`）；Accessibility 已授予；至少 3 名独立评估者在场；有可外部帧采样的手段。缺少评估者或采样手段时不能记完整验收通过；已观察到的运行失败仍据实记录。

步骤：

1. 记录环境：OS/架构、屏幕数/分辨率/缩放/刷新率、浅/深色、减少透明度、高对比、窗口数、材料与 state、复现步骤。任何一步缺记录则该步不成证据。
2. 在诊断页逐档选择 standard（`.hudWindow`）、enhanced（`.popover`）、strongest（`.underWindowBackground`）。2026-10-14 用户验收档位实现并指出增强比最强更模糊，已据此互换上层材料；底层锚点保持 `.popover`。确认三档都使用 state `.active`、blendingMode `.behindWindow`、非激活 borderless panel、`level = .normal`、`ignoresMouseEvents`、`order(.above, relativeTo: 目标)`，并确认三窗都产生覆盖请求。
3. 每档：让 fixture 失焦，3 名评估者在约 50cm、正常缩放下分别尝试读出 12/24/48pt 虚构文本，记录每人能否读出。材料外观不同（深浅/色调）不算 blur 强度差异；变实色不算满足模糊要求。
4. 过渡：观察启用与切档瞬间，panel 首帧是否已经是固定 `.popover` 锚点材料、是否在约 200ms 内过渡到所选档。该锚点不再声明为最强；最低安全模糊须独立验证，存在底层材料不等于隐私已保证。用外部采样分别记录两个指标：(a) 失焦→达到安全模糊，(b) 视觉过渡完成。两者都不等于 API 请求耗时。
5. 撤销：分别制造焦点变化、移动/缩放目标窗口、移除 overlay，确认过渡被取消且不残留半透明层。
6. 减少动态效果开启后重做第 4 步，确认直接取最终状态、不播放动画；减少透明度开启时确认材料路径整体被拒绝（现有策略），不产生实色或半透明替代。
7. 同一次会话顺带跑 F-03（层级/遮挡）与 F-04（一次点击/输入），它们与第 2–5 步共享同一环境。

每个结果能说明什么：

- 先确认该档覆盖层实际有效合成，在此条件下 12pt 仍可辨读 → 该档隐私强度**失败**（记 FAIL 与该档参数）；若层级拒绝已撤层，则记本次运行防护失败，不能直接归因材料强度。
- 三档都不可辨读 → 只是三档候选在本次条件下通过 F-05 的可读性部分；仍需浅/深色、高对比、动态内容与系统设置矩阵，且需要 macOS 14/Intel 与多屏记录才算整项通过。
- 首帧即为锚点材料且过渡不露内容 → 安全起点成立；只有同时给出两个时间指标，才可谈 AC-01 视觉时延。
- 过渡期间出现透明/可读内容 → 记失败并停用该过渡形式，不改成为仅文案动画或实色替代。

决策树不变：层级或输入失败 → 阻断评审；层级与输入通过、只有材料强度失败 → 才进入已批准的 SCK 条件实验；三者都通过 → 继续材料路线。本文件与 [POC_RESULTS](POC_RESULTS.md) 的 Gate 都不能在没有人工作业记录的情况下写成通过。

## 2026-10-13 当前视觉观察与阻断

此前 1 名操作者明确确认合成文字仍可读、没有模糊效果、防护未生效，该旧版本结果记为 FAIL。普通点击输入被报告为正常，但当时覆盖层可能已撤除，不能据此判 F-04 的有效覆盖层穿透通过；3 人独立评估与全部设置组合也未完成。

发布去重修复前，strongest / `.popover` 已选、Experiment On、AX Granted，唯一三窗匹配无问题；即时与后续校验均报告 3 对 `panelMissing`，对应 CG 记录为零 bounds，随后锁存 Cannot protect / Relative overlay order lost 并撤层。该运行失败不证明三档材料都已测过或内在强度不足。

PoCController 的发布去重修复构建并运行后，曾有 3 对层级元数据 ok，但后续 1 对 `unrelatedBetween` 仍使全部覆盖层撤除。停止自动化后的安静人工观察明确为“没有模糊，显示 Cannot protect”；当时 2 对 ok、1 对失败，仍整体撤层，因此这次源码修复未恢复视觉防护。字段已有合成输入也不证明有效覆盖层下的交互。

单窗口失败否决其他正常窗口的耦合已在实验 PoC 中改为按窗口锁存；失败窗口仍撤层，其他窗口仅继续未验证请求。绝对 CG 元数据不可用时，每个尝试窗口仍须锁存失败，保留原有拒绝门槛，独立代码审阅已确认，但尚未实时注入该失败。最终 125 项核心测试与 release 构建等验证通过，不直接覆盖 PoC 具体隔离实现。

用户重新授权最终实验版本后，AX Granted、录屏未授予，唯一三窗匹配无问题；实际 API 工作流出现 1 个窗口锁存 `unrelatedBetween` 并撤层，另外 2 个窗口的未验证请求与 CG 记录保留、常规检查为 ok，界面为 Partial experimental requests (unverified)。停止 GUI 自动化后，操作者明确反馈这两个窗口“有模糊，文字无法读出”。这是 standard / `.hudWindow` 与始终存在的 `.popover` 锚点组合下、1 名操作者的局部正向观察；第三个窗口仍失败，不能证明整体层级或两个窗口已验证受保护。Move、dialog 与自动化恢复前台的因果尚未隔离，详见 [PoC 实测记录](POC_RESULTS.md)。

操作者随后完成本场景的三候选比较，明确反馈“三档都不可读，模糊程度明显不同”。这是单名操作者对两个保留窗口的实际模糊差异观察，并非只有色调变化；不等于量化半径、三名独立评估者或整项 F-05 通过。始终存在的 `.popover` 锚点仍是独立材料归因因素，不否定本次组合的正向效果。第三个窗口仍失败，其他设置、帧时延和真实轮廓未测；反馈后没有再次操作 GUI 或构建测试。

下一步解决 F-03 与真实轮廓，补齐有效覆盖层下的输入、完整可读性与系统设置评估。前台立即撤层和层级失败拒绝仍保留；局部正向观察不等于整体放行。材料观察不属于强度失败，已批准的 SCK 模糊替代条件尚未触发；单独获批的轮廓研究范围见下方，不授权其他捕获实验。Task 8 仍受后续 Gate 阻断，不改变产品保护状态或降低验收要求。

## 结果交付

2026-10-14 用户曾在录屏授权时报告系统恶意软件拦截，当时停止实验且未采集；具体原因仍未确定。后续用户明确确认“可以正常使用继续”，实验在正常安全策略下恢复；不据此推断先前拦截原因或系统误报。

2026-10-13 用户已批准独立的[合成窗口轮廓探针](CONTOUR_SPIKE_PROPOSAL.md)：诊断 app 可手动请求录屏权限，并仅对已验证 fixture 的单窗口帧在本机内存分析外轮廓；不显示、保存或上传原始帧，不采集其他应用。这是轮廓研究用途，既有材料路线不变，不代表 SCK 模糊替代条件已满足，也不直接接入产品保护状态。

2026-10-14 探针已实现，10 项合成分析测试与完整 135 项测试通过，release 构建、plist、ad-hoc 签名、`spctl` 检查及独立源码审阅完成；产品 target 没有新增探针依赖，安装流程已跳过。单次采集限制 fixture 唯一映射、同屏包含与 4 百万像素，取消和失效丢弃迟到结果；原帧仅在内存后台分析，只可输出未验证的中性轮廓候选。严格启发式、混合 DPI、异步生命周期与实际 alpha 均未完成验证。

恢复后首次 3 次合成单窗采集均为歧义，移动/缩放丢弃旧结果。随后将一层邻接 partial 判定改为外缘连通多层 partial 分析，14 项合成用例通过；修正既有测试的当前时间依赖后，最终完整 139 项测试、release 与签名等检查通过，生产日历逻辑未改。新版本实际取得两项权限、Experiment Off 下又静态采集两个 fixture 目标，分别得到 1380×1284 与 1280×1184 的 UNKNOWN / outer contour candidate / unvalidated；中性统一灰色示意可见，目标切换丢弃旧结果，停止研究清除了结果与预览。

共 5 次手动采集，后 2 次为候选；新分类器未重测移动/缩放，全部取消/生命周期交错仍未覆盖。原帧/RGB 只在内存、未显示保存上传、未采集其他应用；示意不含原始内容。候选尚未与真实外缘逐点对照，也没有产品 mask 接入。其他窗口类型、系统版本、多屏/混合 DPI、层级、交互、评估者和时延仍缺证据，独立研究不放行 Task 8 或改变 SCK 模糊替代条件，详见 [PoC 实测记录](POC_RESULTS.md)。

提交一份 `docs/engineering/POC_RESULTS.md`，包含 API 路径、实测表、失败复现步骤、支持矩阵与推荐。每项标为通过、失败、未测，不得把未测当通过。只保留经过脱敏的测试画面；没有用户授权，不采集或上传真实敏感窗口内容。

结论分为：

- **可进入 MVP：**基础真实模糊、层级、输入与权限门槛全部通过，并有明确支持矩阵。
- **需要调整范围：**基础通过、部分系统空间失败，须经产品评审认可受限范围才实施。
- **路线不成立：**基础模糊或层级不能可靠完成，停止功能工程，不以不透明遮罩或私有 API 替代需求。

最初协议阶段没有真机实验结果；当前已执行受控实验并记录防护失败，仍无 MVP 放行结论。具体工程与执行步骤见 [macOS PoC 实施计划](../superpowers/plans/2026-10-11-macos-blur-poc.md)。
