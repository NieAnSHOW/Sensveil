# macOS 模糊保护可行性验证

状态：待执行 · 日期：2026-10-11，2026-10-13 增加三档材料与安全过渡实验协议 · 依据：[PRD](../product/PRD.md)

## 验证问题

在只使用公开 API 的前提下，能否让 Sensveil 在指定应用失焦时对所有受支持可见窗口作不可辨识的模糊，并在聚焦时无阻碍地恢复？需要同时保持其他应用的层级、输入及系统空间行为正确。

用户明确拒绝不透明遮罩。PoC 的结论可以是某路径不成立；不能以实色覆盖证明本需求可行。

## 候选顺序

1. 以不抢焦点的 AppKit 覆盖窗口承载 `NSVisualEffectView` behindWindow 材料，验证跨应用背景模糊、系统设置变化、真实可读性。
2. 如材料路径不满足，验证 ScreenCaptureKit 按目标窗口采集 → Core Image 可控模糊 → 覆盖窗口。原始像素仅在本机内存，不先显示原始帧再补滤镜。
3. 两条都无法同时满足隐私效果、层级和交互时，输出否定结论与具体证据，回到产品决策；不引入私有 CGS API，不偷偷降级遮罩。

## 环境与测量方法

- 基线：macOS 14 和当前稳定系统各至少一台；Apple Silicon 与 Intel 各至少一台，未测试组合标为未验证。
- 应用：Safari、TextEdit、Terminal、一个实际 Electron 应用；多窗口、sheet、弹窗与 helper 分开记录。
- 显示：单屏与双屏，Retina 与非 Retina 混合缩放，窗口跨屏、显示器拔插、不同原点和负坐标。
- 数据：使用虚构姓名、手机号、财务表格及 12/24/48pt 正文，不使用真实个人信息。
- 性能：记录设备、OS、分辨率、窗口数、刷新率、CPU（100% 为一核心）、驻留内存、渲染/采样成本。
- 延迟：单调时钟记录焦点事件、覆盖呈现与撤层；100 次切换的 p50/p95/最大值；另记录新窗口首次呈现到模糊的曝光时间。
- 可读性：约 50cm 正常缩放下，至少 3 名独立评估者尝试读出测试文本；原始帧不得被显示。主观可读性测试是发行条件之一，并非密码学保密保证。

## 必测矩阵

| ID | 试验 | 通过标准 |
| --- | --- | --- |
| F-01 | 枚举与 AX/SCK 窗口映射 | 窗口归属、边界、显示器与坐标正确，不靠私有窗口 ID API |
| F-02 | 应用前台变化、同应用多窗口 | 100 次切换状态一致，全部同应用窗口共同撤层，无焦点循环 |
| F-03 | 多个窗口交叠、别的应用遮挡、点击空白 | 不错误遮住前台或无关应用；层级随目标正确变化 |
| F-04 | 点击后台目标窗口 | 一次点击即聚焦并撤层，鼠标/键盘不被拦截 |
| F-05 | 模糊强度与系统设置 | 浅/深色、减少透明度、高对比下敏感文字不可辨；材料变实色不算满足模糊要求 |
| F-06 | 捕获路径与窗口内容更新 | 按窗口过滤，不捕获覆盖层形成反馈；不闪出原始帧，录屏权限失败明确异常 |
| F-07 | AX 与屏幕录制权限拒绝/撤回 | 状态与真实影响一致，补权限可恢复，无循环授权框 |
| F-08 | 移动/缩放、创建关闭、最小化恢复、应用重启 | 无持续偏移、旧位置漏出、孤立层或复用错误窗口 |
| F-09 | 双屏、混合 DPI、跨屏与拔插 | 遮蔽匹配目标边界，不覆盖空区域或其他窗口 |
| F-10 | Spaces、原生全屏、Stage Manager | 分场景记录；不能仅凭 canJoinAllSpaces 认定外部全屏支持 |
| F-11 | Mission Control、App Exposé、Dock 缩略图 | 记录系统快照是否仍显示原始内容，支持范围据实说明 |
| F-12 | 锁屏、睡眠唤醒、系统权限设置打开 | 重建状态，不把恢复前的旧层误认为已保护 |
| F-13 | 捕获流断开、无图帧、渲染失败 | 不透明遮罩禁用；短暂有效模糊帧策略有上限，失败明确无法保护 |
| F-14 | 10 个可见窗口、静止与动态内容 | p95 目标 ≤150ms、最大 ≤300ms；CPU <5%、内存 <200MiB 候选预算，实测超标须评审 |
| F-15 | 系统截图/录屏/共享捕获目标应用 | 记录捕获的是原窗口还是覆盖合成结果，不宣称全面防截图 |
| F-16 | 退出、强制结束、崩溃 | 无残留阻挡层，明确保护停止而非声称崩溃后仍安全 |

AX 窗口与 SCWindow/CGWindow 元数据的精确映射，以及跨进程窗口 Z-order 的公开实现方式是最高风险。若只能按位置近似匹配，必须记录歧义并证明不会错盖；几何匹配不能自动算通过。

## 三档材料与安全过渡实验协议（2026-10-13 准备，未执行）

目的：在只使用公开 API 的前提下，逐档判定 behind-window 材料能否让 12/24/48pt 内容不可辨（F-05），并验证整体过渡不是从透明状态开始。本协议不改变下面的结论分类；它只把 F-05 从“无候选”变成“有三档可测”。

先决条件：已安装/构建的合成 fixture（3 个内容窗口，唯一标题，12/24/48pt 虚构文本）与诊断 app（`Sources/SensveilPoC`）；Accessibility 已授予；至少 3 名独立评估者在场；有可外部帧采样的手段。缺少评估者或采样手段时全部记未测。

步骤：

1. 记录环境：OS/架构、屏幕数/分辨率/缩放/刷新率、浅/深色、减少透明度、高对比、窗口数、材料与 state、复现步骤。任何一步缺记录则该步不成证据。
2. 在诊断页逐档选择 standard（`.hudWindow`）、enhanced（`.underWindowBackground`）、strongest（`.popover`）。确认三档都使用 state `.active`、blendingMode `.behindWindow`、非激活 borderless panel、`level = .normal`、`ignoresMouseEvents`、`order(.above, relativeTo: 目标)`，并确认三窗都产生覆盖请求。
3. 每档：让 fixture 失焦，3 名评估者在约 50cm、正常缩放下分别尝试读出 12/24/48pt 虚构文本，记录每人能否读出。材料外观不同（深浅/色调）不算 blur 强度差异；变实色不算满足模糊要求。
4. 过渡：观察启用与切档瞬间，panel 首帧是否已经是锚点（声明最强）材料、是否在约 200ms 内过渡到所选档。用外部采样分别记录两个指标：(a) 失焦→达到安全模糊，(b) 视觉过渡完成。两者都不等于 API 请求耗时。
5. 撤销：分别制造焦点变化、移动/缩放目标窗口、移除 overlay，确认过渡被取消且不残留半透明层。
6. 减少动态效果开启后重做第 4 步，确认直接取最终状态、不播放动画；减少透明度开启时确认材料路径整体被拒绝（现有策略），不产生实色或半透明替代。
7. 同一次会话顺带跑 F-03（层级/遮挡）与 F-04（一次点击/输入），它们与第 2–5 步共享同一环境。

每个结果能说明什么：

- 某档在 12pt 下仍可辨读 → 该档隐私强度**失败**（记 FAIL 与该档参数）。
- 三档都不可辨读 → 只是三档候选在本次条件下通过 F-05 的可读性部分；仍需浅/深色、高对比、动态内容与系统设置矩阵，且需要 macOS 14/Intel 与多屏记录才算整项通过。
- 首帧即为锚点材料且过渡不露内容 → 安全起点成立；只有同时给出两个时间指标，才可谈 AC-01 视觉时延。
- 过渡期间出现透明/可读内容 → 记失败并停用该过渡形式，不改成为仅文案动画或实色替代。

决策树不变：层级或输入失败 → 阻断评审；层级与输入通过、只有材料强度失败 → 才进入已批准的 SCK 条件实验；三者都通过 → 继续材料路线。本文件与 [POC_RESULTS](POC_RESULTS.md) 的 Gate 都不能在没有人工作业记录的情况下写成通过。

## 结果交付

提交一份 `docs/engineering/POC_RESULTS.md`，包含 API 路径、实测表、失败复现步骤、支持矩阵与推荐。每项标为通过、失败、未测，不得把未测当通过。只保留经过脱敏的测试画面；没有用户授权，不采集或上传真实敏感窗口内容。

结论分为：

- **可进入 MVP：**基础真实模糊、层级、输入与权限门槛全部通过，并有明确支持矩阵。
- **需要调整范围：**基础通过、部分系统空间失败，须经产品评审认可受限范围才实施。
- **路线不成立：**基础模糊或层级不能可靠完成，停止功能工程，不以不透明遮罩或私有 API 替代需求。

PoC 是下一阶段工作，本轮不包含已执行的真机实验，也没有已通过的结果。具体工程与执行步骤见 [macOS PoC 实施计划](../superpowers/plans/2026-10-11-macos-blur-poc.md)。
