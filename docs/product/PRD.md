# Sensveil 产品需求文档

版本：0.1 · 日期：2026-10-11 · 状态：需求基线已评审，尚未实现产品功能

当前实现与验收状态见 [MVP 验证边界](../engineering/MVP_VALIDATION.md) 和 [开发指南](../engineering/DEVELOPMENT.md)；历史模糊实验记录见 [PoC 结果](../engineering/POC_RESULTS.md)。这些实现状态链接不表示下列验收条件已通过。

## 1. 产品概述

Sensveil 是本地运行的桌面应用隐私防窥工具。用户指定需要保护的应用后，该应用失去前台焦点时，其可见窗口自动模糊；重新聚焦时撤去模糊，恢复正常操作。

一期面向 macOS。Windows 是后续方向，不属于一期开发、测试或宣传支持范围。

### 1.1 需求来源与决策等级

**用户确定的需求：**

- 产品名 Sensveil，仓库为 `NieAnSHOW/Sensveil`。
- 自动定位目标应用窗口，按应用聚焦状态切换整个应用的模糊状态。
- 免费版最多选择 2 款应用；付费版不限应用数量。
- 当前设备首次安装获得 5 天付费版试用。
- 激活码永久激活，人民币 19.9 元绑定 1 台设备，32.9 元绑定 2 台设备。
- 首次激活允许联网，激活后日常长期离线使用。
- **必须保持模糊效果；失败时明确提示无法保护，不接受不透明遮罩降级。**

**已评审的具体化规则：**2026-10-11 用户确认“没问题，可以继续”，接受本 PRD 作为下一阶段需求基线，包括应用级焦点定义、免费配置额度计数、首次启动起连续 120 小时、到期保留策略和菜单栏形态。macOS 14 仍是待 PoC 的系统基线；设备迁移、退款和版本范围等商业细则仍需在收费前确定。

**待技术验证：**跨应用真实模糊的隐私强度、遮挡层级、特殊窗口、全屏与 Spaces 等场景。技术选型是候选路线，文档不表示这些能力已实现。

## 2. 用户、场景与价值边界

| 用户 | 场景 | 要完成的任务 |
| --- | --- | --- |
| 办公人员 | 开放工位、聊天与客户资料窗口常驻 | 切换工作应用后自动隐藏后台敏感内容 |
| 移动办公者 | 咖啡馆、公共交通、共享空间 | 减少频繁最小化、关闭敏感窗口的操作 |
| 多屏用户 | 次屏保留财务、通讯等窗口 | 同时保护多个后台窗口，避免遗漏 |

价值是减少后台窗口意外暴露。当前聚焦应用仍正常显示，旁人仍能看到正在使用的内容。应用选择是由用户完成的，不检测内容是否敏感。

### 2.1 明确的安全边界

- 防窥是视觉隐私功能，不是文件加密、操作系统访问控制或恶意软件防护。
- 不承诺防截图、录屏或屏幕共享；第三方可直接采集原应用窗口，覆盖层未必被一起采集。
- Sensveil 必须在运行，并且具备所需权限；退出、崩溃、权限撤回后不能保证继续保护。
- 不支持的场景必须明确提示，不能以“已保护”状态掩盖失败。
- 窗口枚举与可见性检测可能不完整；诊断必须承认无法检测的系统限制，不能承诺所有遗漏都可自动发现。

## 4. 核心模型与交互

### 4.1 应用与焦点

- 持久身份使用应用 `bundleIdentifier`；运行时使用 PID 关联窗口。名称和图标只用于展示。
- 同一应用无论有多少窗口，只占一个应用额度。升级、退出和重启保留配置。
- 以系统前台应用为“聚焦”判定，同一应用的全部受支持窗口共同撤去模糊。同一应用内两个窗口互相切换，不触发后台窗口模糊。
- 如果以后需要“只解除当前窗口的模糊”，须作为独立窗口级能力重新定义，不能混用。
- 目标应用的多个实例和 helper 窗口须有可验证的归属映射；不能仅凭进程名相似就合并。
- 默认保护明确识别的普通顶层窗口以及可验证归属的 sheet/弹窗。菜单、tooltip、系统弹窗、无法归属的辅助进程属于验证支持矩阵，不能无条件宣传“全部窗口”。

### 4.2 保护判定

```text
可启用 = 用户已选择 && 单应用开启 && 位于当前授权额度 && 全局未暂停
可保护 = 可启用 && 所需权限有效 && 目标应用/窗口受支持 && 模糊引擎正常
需要模糊 = 可保护 && 目标应用不为前台 && 目标窗口当前可见
```

只有收到覆盖层呈现与目标窗口匹配的确认后，才展示“已保护”；事件已发出或设置已开启不等于保护生效。

| 条件 | 窗口行为 | 状态文本 |
| --- | --- | --- |
| 已开启，应用聚焦 | 撤去该应用所有模糊层 | 正在使用 |
| 已开启，应用失焦，覆盖成功 | 对该应用可见窗口模糊 | 已保护 |
| 应用未运行 | 不创建覆盖层，保留配置 | 未运行 |
| 无当前可见窗口 | 清理无效层 | 无可见窗口 |
| 用户关闭单应用开关 | 撤层，保留配置和额度占用 | 未开启 |
| 全局暂停 | 撤去全部模糊层 | 已暂停 |
| 缺权限、模糊失败或窗口不支持 | 不使用实色遮罩；提示影响范围 | 无法保护 |
| 有窗口成功、有窗口失败 | 成功窗口保持模糊，列出异常范围 | 部分窗口无法保护 |
| 超出免费额度 | 保留配置，撤层 | 超出额度，未保护 |

### 4.3 窗口跟踪要求

- 响应应用启动/退出、窗口创建/关闭、移动/缩放、最小化/恢复、显示器增减与分辨率变化。
- 覆盖内容区与可能含敏感信息的标题栏；可不覆盖窗口阴影。模糊层位置按屏幕坐标和实际缩放换算。
- 覆盖层不得激活 Sensveil、抢键盘焦点、阻挡用户切回目标窗口或改变目标应用的前后顺序。
- 用户点击后台目标窗口一次即可使原应用聚焦并撤层；不能要求先点一次覆盖层，再点原窗口。
- 其他应用位于敏感窗口上方时，模糊层不能错误覆盖这些应用；不可用全局置顶矩形替代正确层级。
- 新窗口失焦时需及时保护，但不能承诺窗口首次呈现的任何瞬间都零泄漏；最大曝光时间须实测记录。
- 锁屏、睡眠、唤醒、Space 切换后重新枚举并同步，清理孤立覆盖层。

## 5. 页面与用户流程

### 5.1 菜单栏与主界面

菜单栏显示运行、暂停或异常状态，提供打开管理页、暂停/恢复和退出。异常提示不抢焦点，否则会使正在使用的敏感应用意外失焦。

管理页包含应用列表、添加/删除、单应用开关、即时状态、权限入口和授权状态。添加器列出本机 GUI 应用，支持搜索、显示图标及名称、去重；无 bundle identifier 的应用不能静默使用名称替代身份，应明确标示暂不支持。

设置提供登录启动开关（默认关闭）、权限诊断、用户触发的版本检查与帮助入口。关闭管理窗口不退出菜单栏进程。退出前提示保护将停止，随后完整清理覆盖层与捕获资源。

### 5.2 首次使用

启动 → 说明失焦触发及能力边界 → 按技术路径申请权限 → 选择应用 → 实际切换焦点验证 → 菜单栏常驻。

权限应分用途说明：辅助功能用于窗口定位与变化观察；仅在采集模糊方案需要时申请屏幕录制，不请求与功能无关的权限。拒绝不循环弹系统授权框；应用仍可查看配置、授权和帮助，但明确保护未生效。

### 5.3 日常使用

系统前台应用变化 → 同步目标应用归属与窗口 → 聚焦应用撤层 → 其他已启用应用加模糊 → 确认结果并更新状态。打开 Sensveil 管理页也属于前台切换，目标应用此时按失焦规则保护。

### 5.4 购买与激活

查看价格和设备数量 → 外部购买并获得激活码 → 本机输入 → 联网校验设备名额 → 保存已签名凭证 → 即时解锁 → 后续本地离线验签。

首发建议人工售码或接入现有支付服务；购买渠道、收款主体、客服渠道是商业发行前决策，不在本次初始化中假定已接通。

## 6. 版本与商业规则

| 版本 | 配置额度 | 期限 | 价格 | 网络要求 |
| --- | --- | --- | --- | --- |
| 免费版 | 2 款应用 | 永久 | 0 元 | 日常离线 |
| 首装试用 | 不限 | 连续 5 天，即 120 小时 | 0 元 | 本地起算，无首次试用联网要求 |
| 单设备永久版 | 不限 | 永久 | 19.9 元人民币 | 本机首次激活联网 |
| 双设备永久版 | 每台不限 | 永久，最多绑定 2 台 | 32.9 元人民币 | 每台首次激活联网 |

### 6.1 免费额度

- 额度按配置的应用条目计算，包含未运行或单应用关闭的条目；删除条目释放额度。
- 免费模式阻止添加第 3 款，说明额度与购买入口；不阻止已有前 2 款正常使用。
- 不限制免费用户换选应用，删除后可以添加另一款。付费不限配置数，性能上限仍由硬件与支持矩阵约束。

### 6.2 试用起算与到期

建议首次启动时写入设备试用记录，立即开始连续 120 小时计时，不按累计使用时长计算，权限等待时间包含在试用中。这最接近“初次安装”意图，但安装包本身无法可靠获知用户的实际首次安装时间，因此起算点必须在界面明示。

- 使用 Keychain 保存起算与已见最大时间，卸载重装不主动重置；常规升级不重置。
- 系统时间明显回拨时使用已见最大时间，展示“时间异常”；不误降级已有效永久授权。休眠时间计入试用。
- 完全离线环境、删除 Keychain、系统重装、修改本机时钟可能绕过试用。纯本地方案只能降低普通重装重领概率，不能严格证明“每台物理设备只试用一次”。
- 如果严格防重领成为商业要求，需另外确认首次试用联网，并由服务端登记设备与签发试用凭证；用户目前只批准激活联网。
- 有效永久授权优先于试用状态，不随试用到期降级。
- 到期保留全部配置，按稳定添加顺序将前 2 条设为免费有效，超额条目标记“未保护”。用户可在列表选择其他条目替换前 2 条，不能偷偷继续保护超额应用。
- 到期前 24 小时显示本机提醒；到期时菜单栏、管理页明确显示额度变化。不得弹出会抢焦点的提示窗口，也不发送外部消息。

### 6.3 激活与设备绑定

- 一个激活码对应一种设备数套餐；双设备分别激活，不能复制第一台的凭证到第二台使用。
- 同一设备重复激活须幂等，不重复占名额；多个请求争用最后名额最多一个成功。
- 客户端验签与设备匹配成功才升级。网络断开、服务器异常、码无效、名额已满应分别提示，并保留原有有效授权。
- 永久凭证不设强制定期联网或使用到期日。可选更新请求不能作为继续使用条件。
- 本地防篡改不是绝对防破解；任何设备标识方案都要验证重装、系统迁移和硬件维修行为。
- **长期离线与实时远程吊销不能同时保证。** 服务端停用激活码只能阻止后续签发，不能保证已离线保存的永久凭证立即失效。
- 首发建议换机由人工审核，明确旧机停用义务及重复使用无法实时技术证明；退款、换机次数、大版本升级覆盖、丢码找回和售后渠道须在收费前确定并公开。

## 7. 隐私、存储与权限

本地保存应用身份、保护开关、排序、设置、试用记录及授权凭证。设备私钥、设备绑定材料和试用基准使用 Keychain；非敏感配置使用版本化 Codable 文件，迁移失败保留备份并提示。

若采用捕获方案，原始像素只在本机内存处理，不保存截图、不上传、不缓存到磁盘、不写入日志；仅捕获必要目标，权限说明准确区分屏幕捕获与实际持久录制。

激活请求只传许可必需数据：激活码、设备绑定摘要/设备公钥、客户端版本、协议版本和请求防重放字段。服务端保留许可、名额、审计必需字段及运维访问记录，不收集目标应用列表、窗口标题或屏幕内容。设备摘要是可关联的假名标识，不应宣传为“匿名”。

默认无行为遥测。诊断导出由用户主动操作，排除像素、窗口标题、激活码、私钥和原始设备标识；不能在公开 Issue 请求这些数据。

## 8. 异常与恢复

| 异常 | 必须行为 |
| --- | --- |
| 辅助功能权限撤回 | 明示定位/保护异常，停止错误覆盖；补权限后重新枚举 |
| 捕获权限拒绝或撤回 | 若无已验证的其他真实模糊路径，标示无法保护；不降级实色遮罩 |
| 流中断、模糊渲染失败 | 保留仍有效的模糊帧可作为短暂恢复策略；超出验证阈值标示无法保护，禁止展示原始未模糊帧 |
| 部分窗口不支持 | 保持其他窗口保护，显示受影响范围，整体状态为部分异常 |
| 显示器拔插或 DPI 改变 | 重算坐标与窗口映射，清理旧层；重建完成前不显示全部已保护 |
| Sensveil 崩溃/退出 | 不能保证保护；下次启动提示异常退出并重新校验，不宣称后台仍受保护 |
| 本地配置损坏 | 保留损坏备份，进入可恢复状态；不得静默清空后显示保护正常 |
| 激活失败或凭证损坏 | 原有效凭证不被覆盖；无有效凭证时回到剩余试用/免费，说明原因 |
| 激活服务不可用 | 已激活设备继续离线使用；新激活可重试，不发放伪造成功状态 |

## 9. 验收标准与发布门槛

以下是待实现的验收目标，不是当前实测结果。

| ID | 条件 | 通过标准 |
| --- | --- | --- |
| AC-01 | 前台/后台切换，连续 100 次 | 每次状态正确，无焦点循环；稳态 p95 ≤150ms，最大 ≤300ms，记录首次曝光时间 |
| AC-02 | 同应用 3 个窗口，2 个显示器 | 应用聚焦同时撤层，失焦可见窗口同时模糊；混合 DPI 无错位 |
| AC-03 | 点击后台窗口、叠放其他应用 | 一次点击聚焦，不拦输入、不错误覆盖其他应用、不改变目标窗口顺序 |
| AC-04 | 创建/关闭、移动/缩放、最小化/恢复、重启 | 无残影、孤立层或持续错位；新窗保护延迟有记录 |
| AC-05 | 模糊强度、浅深色、高对比、减少透明度 | 名单/手机号/大字正文在约 50cm 正常显示缩放下不可辨读；由至少 3 人独立评估；任何路径未过即不得称隐私保护 |
| AC-06 | 权限拒绝/撤销、捕获失败 | 明确无法保护，无实色降级或原始帧泄漏，恢复后重建 |
| AC-07 | 免费选择第 3 款、删除替换 | 第 3 款被阻止，删除后可添加，未运行条目也占额度 |
| AC-08 | 首次启动、120h 到期、重装/回拨 | 推荐规则得到验证；到期保留配置，前 2 条继续有效，超额明确未保护 |
| AC-09 | 断网下已激活应用 | 永久授权持续有效，焦点切换与模糊不依赖服务端 |
| AC-10 | 同设备重复、单设备第 2 台、双设备第 3 台、并发 | 重试不增占用；超额拒绝；最后名额只分配一次 |
| AC-11 | 篡改凭证、设备不匹配、非法签名、未知密钥 | 拒绝升级，保留其他有效授权，不泄漏密钥 |
| AC-12 | 唤醒、Spaces、全屏、Stage Manager、Mission Control | 按已公布支持矩阵实测；不支持处如可检测需提示；无法可靠检测/覆盖的关键场景不能宣传全面支持 |
| AC-13 | 本机隐私与网络检查 | 无像素/窗口信息外传、无敏感日志，断网仅影响新激活与主动更新检查 |
| AC-14 | 签名公证安装、更新、卸载重装 | 可安装启动，权限归属稳定，配置与永久授权升级不丢失，试用不主动重置 |

性能预算先作为 PoC 测量目标：10 个可见后台窗口，稳态 CPU 平均 <5%（100% 为单个逻辑核心）、驻留内存 <200MiB，静止时降低采样成本。记录硬件、系统、窗口分辨率、刷新率和 p95；使用捕获路线时根据实测重新评审，不承诺“无限应用”即无限性能。

一期最低 macOS 14 为选型建议；Apple Silicon 与 Intel 均为拟支持架构。两者都需要真机证据，不能以 Apple Silicon 编译通过代替 Intel 运行验证。

## 10. 研发阶段与指标

1. 需求与仓库初始化：本 PRD、技术决策、许可协议草案、验证清单和工程规范。
2. 可行性 PoC：真实模糊、窗口层级、焦点、多屏和权限验证；决定路线及支持范围。
3. 本地 MVP：菜单栏、应用选择、保护引擎、配置、权限、免费版和试用。
4. 商业版本：许可服务、离线验签、售码、售后与升级路径。
5. 发布：兼容性、隐私检查、签名公证、安装升级和条款审核。

核心指标以真机测试和自愿反馈取得：首次成功保护率、焦点呈现延迟、错误覆盖次数、崩溃率、权限恢复成功率。试用转化只在用户允许的统计范围或销售记录中评估；不为了指标增加隐含遥测。

## 11. 风险与待决策

| 风险 | 优先级 | 对策 |
| --- | --- | --- |
| 公开 API 不能可靠实现跨应用隐私模糊与层级 | 最高 | 先 PoC；失败即停，不替换为实色遮罩 |
| 系统任务视图/全屏暴露内容 | 高 | 独立支持矩阵；不得宣传全场景防窥 |
| 模糊材料在系统设置下弱化 | 高 | 真实可读性验收，必要时采用捕获模糊候选 |
| 本地试用被重置 | 中 | 说明保证边界，严格防重领需另确认联网试用 |
| 永久离线与退款/迁移的冲突 | 高 | 在收费前公开政策，不能承诺即时撤销 |
| 私钥泄漏或服务停机 | 高 | 服务端密钥隔离、轮换和备份；已签凭证不依赖服务可用性 |
