# Sensveil 产品需求文档

版本：0.2 · 日期：2026-10-14 · 状态：免费应用与原生分栏布局需求基线，已有产品实现；发布验收尚未完成

当前实现与验收状态见 [MVP 验证边界](../engineering/MVP_VALIDATION.md) 和 [开发指南](../engineering/DEVELOPMENT.md)；历史模糊实验记录见 [PoC 结果](../engineering/POC_RESULTS.md)。这些实现状态链接不表示下列验收条件已通过。

## 1. 产品概述

Sensveil 是本地运行的桌面应用隐私防窥工具。用户指定需要保护的应用后，该应用失去前台焦点时，其可见窗口自动模糊；重新聚焦时撤去模糊，恢复正常操作。

一期面向 macOS。Windows 是后续方向，不属于一期开发、测试或宣传支持范围。

### 1.1 需求来源与决策等级

**用户确定的需求：**

- 产品名 Sensveil，仓库为 `NieAnSHOW/Sensveil`。
- 自动定位目标应用窗口，按应用聚焦状态切换整个应用的模糊状态。
- 全面免费，不限制配置应用数量，不设付费版、试用、购买、激活或设备绑定。
- 核心保护与配置功能离线运行；仅用户主动打开外部链接等操作需要网络。
- 主窗口采用 macOS 原生左右布局，独立设置提升为左侧一级菜单，右侧显示对应页面。
- **必须保持模糊效果；失败时明确提示无法保护，不接受不透明遮罩降级。**

**当前决策：**2026-10-14 用户明确要求全面免费并移除商业化，取代 2026-10-11 的免费额度、120 小时试用、激活及设备套餐规则。应用级焦点定义、菜单栏形态与失败明确提示仍保留。旧报告中的商业验收只作历史记录，不再是当前门槛；macOS 14 与实际兼容性仍以验证结果为准。

**待技术验证：**跨应用真实模糊的隐私强度、遮挡层级、特殊窗口、全屏与 Spaces 等场景。技术选型是候选路线，文档不表示这些能力已实现。

## 2. 用户、场景与价值边界

| 用户 | 场景 | 要完成的任务 |
| --- | --- | --- |
| 办公人员 | 开放工位、聊天与客户资料窗口常驻 | 切换工作应用后自动隐藏后台敏感内容 |
| 移动办公者 | 咖啡馆、公共交通、共享空间 | 减少频繁最小化、关闭敏感窗口的操作 |
| 多屏用户 | 次屏保留财务、通讯等窗口 | 同时保护多个后台窗口，避免遗漏 |

价值是减少后台窗口意外暴露。当前聚焦应用仍正常显示，旁人仍能看到正在使用的内容。应用选择是由用户完成的，不检测内容是否敏感。

### 2.1 明确的安全边界

- 防窥是视觉隐私功能，不是文件加密、操作系统访问控制或恶意软件防护。
- 不承诺防截图、录屏或屏幕共享；第三方可直接采集原应用窗口，覆盖层未必被一起采集。
- Sensveil 必须在运行，并且具备所需权限；退出、崩溃、权限撤回后不能保证继续保护。
- 不支持的场景必须明确提示，不能以“已保护”状态掩盖失败。
- 窗口枚举与可见性检测可能不完整；诊断必须承认无法检测的系统限制，不能承诺所有遗漏都可自动发现。

## 4. 核心模型与交互

### 4.1 应用与焦点

- 持久身份使用应用 `bundleIdentifier`；运行时使用 PID 关联窗口。名称和图标只用于展示。
- 同一应用无论有多少窗口，只保留一个应用配置条目，不设应用数量上限。升级、退出和重启保留配置。
- 以系统前台应用为“聚焦”判定，同一应用的全部受支持窗口共同撤去模糊。同一应用内两个窗口互相切换，不触发后台窗口模糊。
- 如果以后需要“只解除当前窗口的模糊”，须作为独立窗口级能力重新定义，不能混用。
- 目标应用的多个实例和 helper 窗口须有可验证的归属映射；不能仅凭进程名相似就合并。
- 默认保护明确识别的普通顶层窗口以及可验证归属的 sheet/弹窗。菜单、tooltip、系统弹窗、无法归属的辅助进程属于验证支持矩阵，不能无条件宣传“全部窗口”。

### 4.2 保护判定

```text
可启用 = 用户已选择 && 单应用开启 && 全局未暂停 && 当前保护时段有效
可保护 = 可启用 && 所需权限有效 && 目标应用/窗口受支持 && 模糊引擎正常
需要模糊 = 可保护 && 目标应用不为前台 && 目标窗口当前可见
```

保护时段语义（全天/每周/节假日、优先级、DST 与跨午夜规则）见 [TASK.md](../../TASK.md) 第 6 节；实现基线日期 2026-10-13。

只有收到覆盖层呈现与目标窗口匹配的确认后，才展示“已保护”；事件已发出或设置已开启不等于保护生效。

| 条件 | 窗口行为 | 状态文本 |
| --- | --- | --- |
| 已开启，应用聚焦 | 撤去该应用所有模糊层 | 正在使用 |
| 已开启，应用失焦，覆盖成功 | 对该应用可见窗口模糊 | 已保护 |
| 应用未运行 | 不创建覆盖层，保留配置 | 未运行 |
| 无当前可见窗口 | 清理无效层 | 无可见窗口 |
| 用户关闭单应用开关 | 撤层，保留配置 | 未开启 |
| 全局暂停 | 撤去全部模糊层 | 已暂停 |
| 处于指定时段之外 | 撤层，不读取模糊能力错误 | 非保护时段 |
| 节假日日历缺少当年数据 | 按每周规则判定，独立提示 | 节假日日历不可用（独立警告） |
| 缺权限、模糊失败或窗口不支持 | 不使用实色遮罩；提示影响范围 | 无法保护 |
| 有窗口成功、有窗口失败 | 成功窗口保持模糊，列出异常范围 | 部分窗口无法保护 |

### 4.3 窗口跟踪要求

- 响应应用启动/退出、窗口创建/关闭、移动/缩放、最小化/恢复、显示器增减与分辨率变化。
- 覆盖内容区与可能含敏感信息的标题栏；可不覆盖窗口阴影。模糊层位置按屏幕坐标和实际缩放换算。
- 使用完整包围目标矩形的统一圆角外扩覆盖，不匹配目标真实圆角；屏幕外扩部分不向内重算圆角，避免裁掉可见内容。
- 覆盖层不得激活 Sensveil、抢键盘焦点、阻挡用户切回目标窗口或改变目标应用的前后顺序。
- 用户点击后台目标窗口一次即可使原应用聚焦并撤层；不能要求先点一次覆盖层，再点原窗口。
- 其他应用位于敏感窗口上方时，模糊层不能错误覆盖这些应用；不可用全局置顶矩形替代正确层级。
- 新窗口失焦时需及时保护，但不能承诺窗口首次呈现的任何瞬间都零泄漏；最大曝光时间须实测记录。
- 锁屏、睡眠、唤醒、Space 切换后重新枚举并同步，清理孤立覆盖层。

## 5. 页面与用户流程

### 5.1 菜单栏与主界面

菜单栏显示运行、暂停或异常状态，提供打开管理页、暂停/恢复和退出。异常提示不抢焦点，否则会使正在使用的敏感应用意外失焦。

主窗口左侧提供“防窥应用 / 防窥设置 / 权限 / 通用 / 关于”五个一级菜单，右侧显示所选菜单的页面；“关于”固定在左侧底部，与其他入口同级。采用系统侧边栏选择、原生表单分组和标准控件，支持浅深色。2026-10-14 窗口交互调整：侧栏固定 210pt，不提供拖动分隔线或折叠入口；管理窗口内容固定 920 × 700pt，禁用调整大小与全屏，长内容在页面内滚动。全局暂停/恢复移至原生标题栏右上角，保留隐藏窗口标题与透明顶部，由系统处理按钮点击与空白标题区拖动。

“防窥应用”包含应用列表、添加/删除、单应用开关与即时状态；“防窥设置”合并模糊程度、守护文案、固定圆角说明与全天/指定时段、每周和节假日配置，在同一个可滚动页面中分组展示；“权限”包含状态、用途说明、系统设置入口与刷新；“通用”保留登录启动尚未实现的明确说明；“关于”展示应用名、版本、项目与作者链接。防窥设置共用底部悬浮保存/放弃栏，操作栏与页面边缘留出间距，表单预留滚动安全空间；保存一次提交两组草稿，失败保留全部草稿且不提交部分设置。全局暂停/恢复在各页面共用原生标题栏右上控件，随保护状态和界面语言立即更新，只读配置时禁用，点击不得触发窗口拖动；写盘失败仍在共享区域明确提示。添加器列出本机 GUI 应用，支持搜索、显示图标及名称、去重；无 bundle identifier 的应用不能静默使用名称替代身份，应明确标示暂不支持。

2026-10-13 交互补充：可添加应用收纳到“添加应用”弹窗，支持搜索、运行中/已安装分类、刷新和浏览本机应用；管理页只列已添加应用。指定时段先多选周一至周日，再逐一配置各天的多个时段；取消选择将该天设为空，保存后生效，其他日期不联动修改。未接入的模糊档位、守护文案、圆角覆盖和过渡能力必须明确标示未实现，不能用已保存设置暗示窗口效果已生效。

通用提供“跟随系统 / 简体中文 / English”语言选择，默认跟随系统；偏好独立持久化，切换后用户界面立即生效，无需重启。系统语言的任一 `zh` 变体使用简体中文，其他未支持语言回退英文。界面语言不改变应用名称、bundle identifier、技术日志、项目 URL、保护配置或草稿；保护时段仍按本机时区及既定 DST 规则判断。登录启动尚未实现，不提供看似可用的开关；权限诊断放入“权限”。版本展示位于“关于”，不将展示版本号描述为已实现更新检查。关闭管理窗口不退出菜单栏进程。退出前提示保护将停止，随后完整清理覆盖层与捕获资源。

### 5.2 首次使用

启动 → 说明失焦触发及能力边界 → 按技术路径申请权限 → 选择应用 → 实际切换焦点验证 → 菜单栏常驻。

权限应分用途说明：辅助功能用于窗口定位与变化观察；仅在采集模糊方案需要时申请屏幕录制，不请求与功能无关的权限。拒绝不循环弹系统授权框；应用仍可查看配置、权限说明和关于，但明确保护未生效。

### 5.3 日常使用

系统前台应用变化 → 同步目标应用归属与窗口 → 聚焦应用撤层 → 其他已启用应用加模糊 → 确认结果并更新状态。打开 Sensveil 管理页也属于前台切换，目标应用此时按失焦规则保护。

### 5.4 关于

关于入口固定在侧边栏底部。页面放大展示原始品牌图，置于深色中性展示底板上，保持源图构图、透明区域与颜色，使浅深色外观均可辨。

关于页从 `Bundle.main` 的 `CFBundleShortVersionString` 和 `CFBundleVersion` 读取版本与构建号，当前构建为 `0.1.0 (1)`；缺少元数据时显示明确占位，不伪造版本。

## 6. 免费使用规则

Sensveil 全面免费，不区分套餐，不限制配置应用数量，不设使用期限、购买、试用计时、激活服务、离线许可验签或设备绑定。超过两个应用、首次启动满 120 小时或离线状态都不得阻止添加和保护应用。硬件性能与窗口支持矩阵仍约束实际保护能力，不承诺无限性能。

升级保留已有应用、开关、排序、全局暂停和设置。历史商业状态不再参与保护判定，也不应创建或更新试用记录、设备绑定材料；不得因旧商业数据缺失或损坏降级保护。免费使用政策不改变仓库现有代码版权许可，详见 [免费使用与离线政策](../architecture/LICENSE_PROTOCOL.md)。

## 7. 隐私、存储与权限

本地保存应用身份、保护开关、排序和设置，使用版本化 Codable 文件；迁移失败保留备份并提示。不为商业许可创建 Keychain 试用记录、设备私钥或设备绑定材料。

若采用捕获方案，原始像素只在本机内存处理，不保存截图、不上传、不缓存到磁盘、不写入日志；仅捕获必要目标，权限说明准确区分屏幕捕获与实际持久录制。

核心保护与配置无许可服务依赖，不发送激活、试用或设备绑定请求，不收集目标应用列表、窗口标题或屏幕内容。

默认无行为遥测。诊断导出由用户主动操作，排除像素、窗口标题、密钥和原始设备标识；不能在公开 Issue 请求这些数据。

## 8. 异常与恢复

| 异常 | 必须行为 |
| --- | --- |
| 辅助功能权限撤回 | 明示定位/保护异常，停止错误覆盖；补权限后重新枚举 |
| 捕获权限拒绝或撤回 | 若无已验证的其他真实模糊路径，标示无法保护；不降级实色遮罩 |
| 流中断、模糊渲染失败 | 保留仍有效的模糊帧可作为短暂恢复策略；超出验证阈值标示无法保护，禁止展示原始未模糊帧 |
| 部分窗口不支持 | 保持其他窗口保护，显示受影响范围，整体状态为部分异常 |
| 显示器拔插或 DPI 改变 | 重算坐标与窗口映射，清理旧层；重建完成前不显示全部已保护 |
| Sensveil 崩溃/退出 | 不能保证保护；下次启动提示异常退出并重新校验，不宣称后台仍受保护 |
| 本地配置损坏 | 保留损坏备份，进入可恢复状态；不得静默清空后显示保护正常 |

## 9. 验收标准与发布门槛

以下是待实现的验收目标，不是当前实测结果。

| ID | 条件 | 通过标准 |
| --- | --- | --- |
| AC-01 | 前台/后台切换，连续 100 次 | 每次状态正确，无焦点循环；稳态 p95 ≤150ms，最大 ≤300ms，记录首次曝光时间 |
| AC-02 | 同应用 3 个窗口，2 个显示器 | 应用聚焦同时撤层，失焦可见窗口同时模糊；混合 DPI 无错位 |
| AC-03 | 点击后台窗口、叠放其他应用 | 一次点击聚焦，不拦输入、不错误覆盖其他应用、不改变目标窗口顺序 |
| AC-04 | 创建/关闭、移动/缩放、最小化/恢复、重启 | 无残影、孤立层或持续错位；新窗保护延迟有记录 |
| AC-05 | 模糊强度、浅深色、高对比、减少透明度 | 名单/手机号/大字正文在约 50cm 正常显示缩放下不可辨读；由至少 3 人独立评估；任何路径未过即不得称隐私保护 |
| AC-06 | 权限拒绝/撤销、捕获失败 | 明确无法保护，无实色降级或原始帧泄漏，恢复后重建 |
| AC-07 | 添加三个及更多应用、关闭/删除/重新添加 | 不出现额度阻止、升级提示或商业状态，按应用身份去重 |
| AC-08 | 首次启动、超过 120 小时、旧商业数据缺失或损坏 | 核心功能不受试用或许可状态影响，配置保留 |
| AC-09 | 完全断网运行 | 焦点切换、模糊与配置不依赖服务端，不发起商业请求 |
| AC-10 | 一级菜单切换、固定窗口、浅深色 | 五个菜单显示对应页面；侧栏宽度固定，窗口不可调整大小或全屏；标题栏右上暂停/恢复可操作且不拖动窗口；防窥设置共用悬浮保存/放弃栏，滚动到底不遮挡内容，中英文标准控件可操作 |
| AC-11 | 关于版本与链接 | 版本来自 Bundle 元数据，项目及作者链接正确且仅点击后打开 |
| AC-12 | 唤醒、Spaces、全屏、Stage Manager、Mission Control | 按已公布支持矩阵实测；不支持处如可检测需提示；无法可靠检测/覆盖的关键场景不能宣传全面支持 |
| AC-13 | 本机隐私与网络检查 | 无像素/窗口信息外传、无敏感日志，核心使用不依赖网络，外部链接仅由用户主动打开 |
| AC-14 | 签名公证安装、更新、卸载重装 | 可安装启动，权限归属稳定，配置升级不丢失，旧商业数据不再影响功能 |

性能预算先作为 PoC 测量目标：10 个可见后台窗口，稳态 CPU 平均 <5%（100% 为单个逻辑核心）、驻留内存 <200MiB，静止时降低采样成本。记录硬件、系统、窗口分辨率、刷新率和 p95；使用捕获路线时根据实测重新评审，不承诺“无限应用”即无限性能。

一期最低 macOS 14 为选型建议；Apple Silicon 与 Intel 均为拟支持架构。两者都需要真机证据，不能以 Apple Silicon 编译通过代替 Intel 运行验证。

## 10. 研发阶段与指标

1. 需求与仓库初始化：本 PRD、技术决策、免费使用政策、验证清单和工程规范。
2. 可行性 PoC：真实模糊、窗口层级、焦点、多屏和权限验证；决定路线及支持范围。
3. 本地 MVP：菜单栏、应用选择、保护引擎、配置、权限和原生分栏界面。
4. 发布：兼容性、隐私检查、签名公证、安装升级和条款审核。

核心指标以真机测试和自愿反馈取得：首次成功保护率、焦点呈现延迟、错误覆盖次数、崩溃率、权限恢复成功率。不为了指标增加隐含遥测。

## 11. 风险与待决策
